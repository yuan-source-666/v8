# 自建自训小 LLM —— 架构设计蓝皮书（v1.0）

> 路线：C（从零预训练 → SFT → DPO → 自我进化闭环）
> 定位：融合「主流成熟组件 + 前沿架构 + 最新自我进化研究」的个人可落地方案
> 版本日期：2026-09-02 · v1.2（新增动机机制设计与小模型自进化强化）

---

## 0. 设计总纲

### 0.1 为什么这样设计

传统范式（人工标注 → 监督微调）正逼近天花板：高质量人工标注昂贵、专家反馈无法规模化，且在高难任务上人类认知边界反而成为模型进化上限。2026 年的主流共识从"人类教模型"转向"模型自我提升（Self-Improvement）"——人类只需启动系统，模型通过自身能力驱动数据获取、筛选、优化与推理改进，形成可持续闭环。

本架构的目标不是复刻大厂千亿模型，而是**在一张消费级显卡上，训练出一个能自我对话、自我评估、自我迭代的小模型**，完整走通"预训练 → 对齐 → 自进化"全过程，并保留接入鸿蒙端侧部署的能力。

### 0.2 三层架构总览

```
┌─────────────────────────────────────────────────────────┐
│  Layer 3  自我进化闭环（Self-Improvement Loop）          │
│  数据获取 ─▶ 数据筛选 ─▶ 模型优化 ─▶ 推理细化           │
│              ▲           │              │                │
│              └──── 自动评估（贯穿控制层）──┘              │
├─────────────────────────────────────────────────────────┤
│  Layer 2  训练管线（Training Pipeline）                  │
│  预训练(Pretrain) → SFT → DPO/GRPO → 持续自进化训练      │
├─────────────────────────────────────────────────────────┤
│  Layer 1  底座网络（Hybrid Mamba-Transformer）           │
│  GQA + RoPE + SwiGLU + RMSNorm + Mamba-2 SSM 混合层      │
└─────────────────────────────────────────────────────────┘
```

- **Layer 1 决定"模型能学多好"**（容量与效率）
- **Layer 2 决定"模型学到什么"**（通用能力 + 对话对齐）
- **Layer 3 决定"模型能否自己变强"**（差异化竞争力）

## 1. Layer 1 —— 底座网络架构

### 1.1 架构选型结论

采用 **Hybrid Mamba-Transformer**（混合式）：主干为 Decoder-only Transformer，但将大部分自注意力层替换为 Mamba-2 状态空间层。此方案不是实验性设想，而是 2025-2026 年小模型领域的已验证工业路线，代表作为 NVIDIA **Nemotron Nano 2**：其 62 层骨干中约 92% 的自注意力层被替换为 Mamba-2，具体为 6 层多头自注意力 + 28 层 Mamba-2 + 28 层 FFN。

**为什么混合而非纯 Transformer / 纯 Mamba：**

| 方案 | 优势 | 短板 |
|------|------|------|
| 纯 Transformer | 资料多、稳定、质量上限高 | 长上下文 O(n²)，显存/推理开销大 |
| 纯 Mamba/SSM | 线性复杂度、长上下文友好、推理快 | 强检索/复制类任务略弱、生态相对少 |
| **混合（本方案）** | **兼顾两方优点**，全局 attention 兜底检索能力 | 工程上略复杂 |

### 1.2 网络组件清单

| 组件 | 选择 | 理由（可溯源） |
|------|------|----------------|
| 归一化 | **RMSNorm**（pre-norm） | 现代小模型事实标准，省算力、稳定 |
| 前馈 | **SwiGLU**（门控激活） | 主流小模型标配，同等参数量表达更强 |
| 注意力 | **GQA 分组查询注意力** | Qwen/Llama 均采用，显著降 KV 内存、支持长上下文 |
| 位置编码 | **RoPE 旋转位置编码** | 外推性好，128K 上下文可行 |
| 替换层 | **Mamba-2 SSM（SSD 层）** | 线性复杂度长序列建模；SSD 统一了 SSM 与 attention |
| 参数初始化 | 去偏置 + 深度缩放（如 scaled init） | 深网络稳定训练的前提 |
| 精度 | bf16 混合精度（进阶可试 FP8） | bf16 单卡即可训，FP8 为 Nemotron 路线减内存 |

### 1.3 层混合布局（推荐）

以 12 层骨干为例（每 3 层为一组）：[M, M, A] 交替 → 即 8 层 Mamba-2 + 4 层自注意力。注意力层放在靠近输出的位置以强化全局检索/指令跟随。参考 Nemotron 的经验，SSM 层占比可到 80%~90%，但从个人可调试性出发，建议先 60%~70% 起步。

### 1.4 可选前沿扩展（按投入产出排序）

1. **BitNet / 1.58-bit 化训练**：权重低比特直接训练，推理和部署省一个量级，是端侧化关键——但训练工程复杂度高，留到二期。
2. **细粒度 MoE**：小模型上引入稀疏专家提升容量，代价是训练复杂度和调参难度，二期评估。
3. **KV-Cache / 状态压缩**：Mamba-2 本身无 KV cache，是长上下文端侧部署的天然优势，设计时保留。

### 1.5 三档模型规模配置

| 配置 | 参数量 | 层数 | d_model | 混合布局 | 显存需求(约) | 用途 |
|------|--------|------|---------|----------|--------------|------|
| Tiny | ~33M | 6 | 512 | 4M+2A | 4~6G | 机制验证、快速迭代 |
| Base | ~150M | 12 | 768 | 8M+4A | 8~12G | 主战场、完整闭环 |
| Pro | ~1B | 24 | 1536 | 18M+6A | 24G / 云 GPU | 追求质量、端侧部署 |

**建议从 Base 起步（原结论，需独立 GPU）**：150M 恰好能在单卡 12G 上跑通全流程。但经实测，本机**无独立显卡、CPU-only**，该建议失效，落地规模见 1.6 节。

### 1.6 硬件适配：CPU-only 约束下的落地结论（v1.1）

**实测硬件**：Intel Core Ultra 7 255H（16 核 16 线程）/ 32GB LPDDR5 / 无独显，仅 Intel Arc 140T 集显（4GB 共享）。瓶颈为**纯 CPU 算力**，非核数。

| 配置 | 参数量 | CPU 训练可行性 | 定位 |
|------|--------|----------------|------|
| Mini | ~10M | 舒适区，1~2 天内跑通全流程 | 纯机制验证，日级产出 |
| **Tiny（主攻）** | **~33M** | 16 核全开 + IPEX 优化，预训练约 2~3 天 | **本机主战场**，真实闭环 |
| Base 150M | 150M | 需数周，不推荐本地 | 留作云 GPU 提速目标 |

**CPU 训练吞吐依据（可复核）**：PyTorch CPU 后端在 16 线程下，33M 级模型约 2~5k tokens/s（取决是否启用 Intel 优化），按 100M token 语料计预训练约 33~100 小时（约 2~4 天）。数据量、词汇表与参数量三者的乘积直接决定天数，必须同步压缩。

## 2. Layer 2 —— 训练管线

### 2.1 阶段划分

```
Stage 0  Tokenizer      GPT-2 BPE(tiktoken) / SentencePiece，词表 8K~32K
Stage 1  预训练         bf16 + 梯度累积，领域语料（中文/代码）→ 得到底座
Stage 2  SFT            指令数据监督微调 → 学会对话与指令跟随
Stage 3  偏好对齐       DPO（首选）→ GRPO（进阶，无需奖励模型）
Stage 4  自我进化       进入 Layer 3 闭环，持续迭代
```

### 2.2 关键工程决策

- **预训练框架**：PyTorch 手写训练循环 或 基于 nanoGPT/OpenLM 改造；不直接上 HF Trainer，保证对底层实现有完全掌控（符合"基于源码、可复核"原则）。
- **学习率调度**：Warmup + Cosine Decay，峰值 LR 按小模型经验值 1e-3 量级；配合梯度裁剪。
- **数据配比**：领域语料为主（如中文技术语料、代码库），混入通用语料防止过窄。
- **对齐方法选型理由**：DPO 无需训练奖励模型、实现简单、1B 以下彻底可行；GRPO（DeepSeek 路线）用采样组内相对优势，免 RM 且适合推理类任务，作为进化阶段主力。

## 3. Layer 3 —— 自我进化闭环（核心章节）

> 依据：2026 年 113 页自我提升全景综述（涵盖 500+ 文献）提出的 **LLM Self-Improvement System** 闭环范式。该框架将自我进化收敛为四个环节，由自动评估贯穿全程。

### 3.1 整体闭环

```
        ┌────────────── 自动评估（贯穿控制层） ──────────────┐
        ▼                                                    ▲
  ① 数据获取 ─▶ ② 数据筛选 ─▶ ③ 模型优化 ─▶ ④ 推理细化 ──┘
        │              │            │           │
  模型当学生          择优          SPIN/DPO     反思/自洽
  环境交互          难度过滤       蒸馏自身      测试时计算
  合成生成          多样性选样      在线 RL
```

### 3.2 ① 数据获取（Data Acquisition）

三条递进路径，从"用已有数据"走向"自主创造数据"：

| 路径 | 做法 | 启动成本 |
|------|------|----------|
| 静态筛选 | 从已有语料中挖掘可学习样本（困惑度/多样性过滤） | 低 |
| 环境交互 | 模型通过工具/代码执行/检索获得反馈信号（如写代码跑测试拿 pass/fail） | 中 |
| **合成生成** | 模型自己构造新的训练数据（self-instruction、自问自答、主题扩展） | 中（本方案重点） |

**设计要点**：第一版先用"静态筛选 + 少量合成补强"，等模型有一定质量（SFT 后）再打开合成生成，否则容易放大初始缺陷。

### 3.3 ② 数据筛选（Data Selection）

- **质量维度**：自动评估打分（见 3.6），过滤低质量合成样本——这是防"垃圾进垃圾出"的唯一闸门。
- **多样性维度**：嵌入去重 + 主题聚类配额，防止合成数据坍缩到窄分布。
- **难度维度**：优先纳入"模型当前做错、但接近能做对"的样本（课程式学习，中等难度最佳）。

### 3.4 ③ 模型优化（Model Optimization）—— 自博弈三件套

1. **SPIN 自博弈**（Self-Play Imitation）：模型与自己的"历史版本"对弈。参考模型 = 前一版模型的指数移动平均（EMA）；损失函数让模型学会"偏好数据集中的真样本，而非自己生成的样本"：

   ```
   SPIN Loss = -log σ( λ · ( (P_real - Ref_real) − (P_gen - Ref_gen) ) )
   ```

   用数学用语说：它在一对一比较中挤压自生成样本的 logit，本质是**无需人工偏好标注的自我对弈对齐**，与 AlphaZero 哲学同源。

2. **自我奖励（Self-Rewarding LM）**：让模型生成指令 → 自评答案质量 → 用自评分作为偏好对喂给 DPO/SPIN。模型既是学生又是老师，迭代后可同时提升生成与评判能力（2025-2026 已验证路线，lucidrains 有开源实现 `self-rewarding-lm-pytorch` 可对照源码复核）。

3. **在线强化（GRPO/在线 DPO）**：进入环境交互后，用代码执行结果 / 验证器反馈构造偏好对，做在线策略更新。这是从"离线模仿自己"升级到"从真实反馈学"的通道。

### 3.5 ④ 推理细化（Inference Refinement）

自我进化不只是"改权重"，也包括**不改权重、只在推理时变强**（测试时计算）：

- **Self-Consistency**：同一问题采样 N 次，多数投票/聚类取最终答案。
- **反思（Reflection / Self-Refine）**：先生成 → 自查错误 → 修订，两轮迭代显著提分。
- **验证器重排（Best-of-N）**：用 LLM-as-judge 或小验证器对 N 个候选打分取最优。
- **意义**：这一步产出的高质量轨迹又可回灌进 ① 数据获取，形成"推理 → 数据 → 训练"正向飞轮，正是自我进化区别于普通"微调"的本质。

### 3.6 自动评估（贯穿控制层）

自我进化的**先决条件**——没有评估闭环，进化无从谈起。

| 层级 | 手段 | 作用 |
|------|------|------|
| 高速轻量 | 规则/可执行检验（代码跑测试、数学核验） | 客观信号，最可靠 |
| 中速 | 小验证器（可学习，预测答案好坏） | 可扩展、成本可控 |
| 慢速精确 | LLM-as-Judge（自评 + 交叉评） | 主观质量、多样性 |
| 校准 | 每轮与冻结的基线模型对拍（holdout 集） | 防止整个闭环跑偏/退化 |

**关键设计**：保留一个**冻结的 Reference 模型 + 固定评测集**作为"锚"，每轮进化后必须证明自己比锚更强（胜率 > 50%），否则回滚该轮更新——这是防"自我劣化/模式坍塌"的硬保险。

### 3.7 防塌陷三原则（必须内建）

自我进化最常见的失败是**模式坍塌 / 自我放大偏差**。三条硬约束：

1. **人口不可替换**：合成数据永远与真实语料保持 ≥ 60% 混合比例（参考模型自噬研究结论）。
2. **锚定校验**：见 3.6 校准层，每轮必须有客观基准胜出。
3. **多样性监控**：跟踪生成分布的熵/嵌入多样性，低于阈值自动暂停合成数据生成。

## 5. 风险与边界（诚实声明）

- **小模型自我进化的天花板是真实的**：合成数据增益会被模型自身能力上限锁死，达瓶颈后需要更强模型蒸馏或更多真实数据——这是物理约束，不是工程缺陷。预期 Base 配置自进化带来的提升是"插件式"（单点任务 +5~15%），而非质变。
- **数据集合法性**：选用的开源语料需确认 License 允许商用/再分发。
- **计算成本曲线**：自我进化每轮都要采样+评估，算力消耗超过普通微调，需量入为出。
- **CPU-only 时间成本（本机最现实约束）**：全流程按 3~4 周计划，任何"想多训大一点"的冲动都会指数级放大等待时间；建议严格按 Mini → Tiny 两档节奏推进，先证明闭环再谈规模。
