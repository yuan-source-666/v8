## 0. 三句话摘要

1. **这不是一个"训一个模型"的规范，而是"驯养一个能自进化的智能体"的规范**。v8 的真正特殊性在于三层结构：混合计算底座（Layer 1）+ 训练管线（Layer 2）+ **自进化闭环与恐惧欲望驱动（Layer 3 / v1.2 动机机制）**。前两层只是手段，第三层才是这个架构与其他小模型脚手架的本质区别。
0. **数据已就绪**：SkyPile-150B 中文子集（29,631 篇 / 2940 万汉字 / **6009 万 token**，Apache/Skywork 社区许可）已下载、分词、落盘为 `data/tokens/mini_{train,val}.npy`，真实语料端到端训练已用 5 步验证通过（val_loss 10.56 可算）。
2. **计算底座有实测硬约束**：Mamba-2 实现是 O(L²) 二次复杂度（非理论线性 SSD），CPU 上 Mamba 层比 Attention 层慢 2~3 倍（纯 einsum 无 oneDNN 优化）；`mini` 实测 20M / `tiny` 实测 54M（gpt2 词表虚高）。一切进化计划必须按此排算。
3. **诚实边界**：预训练（含 drives）、推理细化（self-consistency）已完整可用；**drives 目前只接入预训练**，SFT/DPO 未接入；SFT/DPO 暂不能从文件加载真实数据；SPIN/自我奖励/GRPO/自动评估均未实现。文档每步都标注「现在可做 / 待开发」。

## 1. 架构特殊性（本文档核心视角）

> 所有训练方法定制，都从"这个架构特殊在哪"出发，而不是套用通用 LLM 训练经验。

### 1.1 特殊性 A —— 计算架构：Hybrid Mamba-Transformer（实测校准）

| 事实 | 实测证据 | 对训练方法的影响 |
|---|---|---|
| Mamba-2 `ssd_scan` 是 **O(L²) 二次复杂度**（SSD 矩阵对偶形式，未做分块近似，构造完整 L×L 上三角衰减矩阵） | 代码审查：`einsum("b t h s, b m h s -> b h t m")` 输出 T×T 关联矩阵 | **压序列长度是必要手段**，不是可选项；"Mamba 线性复杂度=长序列免费"在这个实现里不成立 |
| CPU 上 **Mamba 层比 Attention 层慢 2~3 倍** | 实测（2 核，d=256）：seq 128/256/512 时 Mamba 14.5/27.1/81.6ms，Attention 4.5/8.7/39.5ms | 6 层 MMA（4 Mamba + 2 Attn）中 **Mamba 是训练主瓶颈**；布局可权衡（见 §1.1.1） |
| 随 seq 增大，Mamba/Attn 比值收敛（3.23x→1.28x） | seq 512→1024：Mamba 81.6→506.8ms（6.2x），Attn 39.5→396.3ms（10x） | 长序列下二者都二次膨胀，**无一例外都要压 seq** |
| Attention 有 causal mask、**无 padding mask**；Mamba 无 mask 概念 | 代码审查：`triu` 仅屏蔽未来 | 微调变长数据**不能用无脑补零**（见 §8 对齐规范） |
| 推理**逐 token 全序列重算，无 KV/Mamba 状态缓存** | 代码审查：`generate()` 每步 `model(x)` 用完整 x | 生成成本 O(L²)·步数；`max_new_tokens` 要小、self-consistency 采样数要控制（见 §10） |
| bf16 autocast（CPU）可用 | 实测冒烟 + 训练 | Mamba 的 `A_log/dt_log` 指数运算在 bf16 下需小步验证，纳入 D3 |

**1.1.1 布局权衡（新增定制维度）**
- 现状：`[M,M,A]×2`，Mamba 占比 2/3。蓝皮书依据 Nemotron 路线选 Mamba 为主，但在**纯 CPU + 纯 PyTorch einsum 实现**下，Mamba 反而更慢。
- 决策建议：**本期保持 `[M,M,A]` 不变**（不改架构、便于对照蓝皮书）；在训练日志里记录各层耗时占比，若 Mamba 瓶颈显著，二期评估 `[M,A,M,A]`（1:1）或对 `ssd_scan` 做分块 SSD 优化（把 O(L²) 降到 O(L·chunk²)，待开发项）。
- **禁止**：因 Mamba 慢就擅自把它从架构里删掉——那等于放弃这个项目的核心特色（线性复杂度 + 长序列潜力的设计意图），只应通过「压 seq + 优化算子」解决。

### 1.2 特殊性 B —— 自进化闭环（Layer 3）

```
数据获取 ─▶ 数据筛选 ─▶ 模型优化 ─▶ 推理细化
   ▲           │           │           │
   └──────── 自动评估（贯穿控制层）──────┘
```
- **本质**：模型既是学生也是老师，通过"生成→筛选→再训练"持续自我提升，人类只启动系统。
- **防塌陷三原则（必须内建）**：① 合成数据 ≤40% 混真实语料；② 保留冻结基线锚定校验（每轮胜率 >50%，否则回滚）；③ 生成多样性监控（低于阈值停合成）。
- **CPU 成本曲线**：进化每轮 = 采样 + 评估 + 再训练，成本是普通微调的 2~3 倍。**必须量入为出**：先手动闭环（人工筛选），再谈自动化。
- **代码现状**：已具备「离线闭环骨架」（预训练→SFT/DPO 链路→sample self-consistency 回灌）；SPIN/自我奖励/GRPO/LLM-as-Judge **未实现**（诚实清单见 §11.2）。

### 1.3 特殊性 C —— 恐惧欲望驱动（drives L2 稳态机制，v1.2 核心）

**设计哲学**：给训练过程装一套"稳态控制系统"——**欲望引导模型趋近目标状态，恐惧约束模型不越出安全边界**。这不是训练后加的技巧，而是嵌入优化循环的控制层。

**机制（已实现的代码行为）**：
```
内部状态 S(t)：resources/energy/consistency/safety_margin/desire/fear（各有 setpoint 与 low/high 边界）
稳态偏差 D = |S − setpoint|            → 欲望项（w_desire）/ 恐惧项（w_fear）
恐惧刹车：fear 高时 brake = 1 − 0.2×fear 降低有效 lr（稳态刹车，真实影响优化）
drv_loss：把 D 接进总损失（w_reg 加权）→ 驱动状态向 target_state 趋近
状态演化输入：loss EMA / loss delta / loss var / grad_norm（compute_state_deltas）
```

**对训练方法的特殊要求（这是普通训练规范没有的）**：
1. **drives 依赖稳定的 loss 指标**：batch 过小 → loss 噪声大 → 状态信号抖动。**定制有效 batch 时必须保证 loss 平滑**（有效 batch ≥ 32 tokens 预算见 §7.3）。
2. **恐惧刹车与学习率调度耦合**：warmup 期间 loss 波动大、fear 可能误报 → 建议 **warmup 阶段后（step > warmup_iters）再让恐惧刹车完全生效**（代码目前从 step 0 即生效，若发现 step 早期 fear 异常可加闸门，待开发）。
3. **drives 的"稳态"是健康信号**：长期 [稳态] 正常；频繁 [临界]（fear>0.8 越界）表示训练状态异常，必须停训排查。
4. **代码边界**：drives **现仅接入预训练（train.py `--use-drives`）**。SFT/DPO 接入（恐惧刹车、drv_loss 扩展）是「待开发项」，属本期可做的小扩展。

## 3. 定制决策（D1–D6）

| # | 决策 | 结论 | 理由 |
|---|---|---|---|
| D1 | 词表 | 保留 gpt2（50257），接受参数量虚高 | tiktoken 免训练、与蓝皮书一致；换小词表二期 |
| D2 | 档位 | mini 只做验证标定，tiny 主战场 | 实测 20M/54M，按实测排算 |
| D3 | 精度 | bf16 主用 + float32 兜底；**专项验证 Mamba 层 bf16 稳定性** | autocast 实测可用；Mamba 指数算子需单独确认 |
| D4 | 序列长度 | **seq 256 起步，实测后决策**（见 §3.1） | Mamba/Attn 均 O(L²)，压 seq 收益 3~4.5x/层 |
| D5 | 语料规模 | mini 5~10M / tiny 20~50M tokens | CPU 宁少勿多，先闭环再扩量 |
| D6 | **进化导向步数预算** | 预算不是"训到 loss 收敛"，而是"够完成一次进化闭环" | 每轮进化含采样+训练，步数按闭环迭代数倒推（§11） |

### 3.1 D4 序列长度决策实验（真机必做）
1. 用 mini 档分别跑 `--max-iters 50`，seq=256 与 seq=512（改 config 覆盖）。
2. 记录 tok/s 与每步耗时，对比 §1.1 基准曲线。
3. 判定：若 256 档 tok/s ≥ 512 档的 **1.8 倍** → 锁定 256；否则可试 384。
4. **不要**在 seq 决策前启动正式训练。

## 8. 对齐/微调数据规范（架构特殊性 A 的落地）

> 因为 Mamba 无 mask、Attention 无 padding mask，变长数据拼接是**架构特有风险**，普通 Transformer 微调经验不适用。

- **禁止无脑补零**：`pad=0` 会被 Mamba 当作真实输入吸收进状态。若沿用现有 `get_batch` 的补零方式，仅用于链路验证。
- **真实数据两条路**：
  1. 等长截断：所有样本截到固定 `max_len`（简单，浪费少量尾部）；
  2. 分段对齐：样本间用 `<|endoftext|>` 分隔、整句切齐（推荐，待开发：sft.py 增加"样本打包 + 分隔符"逻辑）。
- SFT 的 `targets=-100` 已正确屏蔽回答区之外 loss，但 **Mamba 前向仍会计算 padding 位置**（浪费算力 + 状态污染尾部）→ 等长截断 + 合理 max_len（128~256）是当前最稳选择。

## 10. 自进化闭环规范（主线执行流程）

### 10.1 一期：手动闭环（现在可做）
```
底座(SFT后) ─▶ sample self-consistency 采样 ─▶ 人工/规则筛选 ─▶ 合成数据(≤40%)混真实语料
     ▲                                                            │
     └──────────────── 重切 prepare --force ─▶ 再训练/微调 ───────┘
```
- 每轮产出：候选答案集 + 筛选记录 + 混合语料。
- **锚定校验（防塌陷）**：每轮用冻结的上一版模型在固定评测集对拍，胜率 ≤50% 则**回滚该轮**（手动执行）。
- **多样性监控**：肉眼检查生成文本重复率/分布；异常即停。

### 10.2 二期：自动化（待开发，按优先级）
| 项 | 内容 | 优先级 |
|---|---|---|
| SFT/DPO 数据加载 | `--data jsonl` | P0 |
| drives 接入 SFT/DPO | 复用预训练 drives 逻辑 | P0 |
| prepare 目录合并 | real/ + synth/ 自动混合 | P1 |
| 自动评估器 | LLM-as-Judge / 小验证器 | P1 |
| SPIN 自博弈 | EMA 参考模型 + 对弈损失 | P2 |
| 自我奖励 | 自评分偏好对喂 DPO | P2 |
| GRPO / 在线 RL | 环境反馈在线更新 | P3 |

### 10.3 恐惧欲望驱动的进化角色（设计意图）
- **欲望 = 进化方向**：`target_state`（resources 0.90 / energy 0.60 / consistency 0.85 / safety_margin 0.80）给出"健康模型"应趋近的内部状态，drives 在训练中持续朝它拉。
- **恐惧 = 进化刹车**：当 loss 恶化（var 上升/EMA 回升/grad_norm 异常）→ fear 上升 → 有效 lr 降低，防止一轮进化把模型训坏。
- **落地现状**：这套机制在预训练已生效；进化闭环中"再训练"环节若接入 drives（待开发），即完成"恐惧欲望贯穿自进化"的设计闭环。

## 13. 风险与决策树

| 症状 | 排查顺序 |
|---|---|
| 训练极慢 | ① 线程/oneDNN ② **seq 决策实验是否做了** ③ Mamba 层耗时占比 ④ 换布局（二期） |
| loss 不降 | ① 关 drives 复现 ② lr/warmup ③ 语料 ④ 缩小模型 |
| drives 频繁 [临界] | ① 有效 batch 是否过小 ② warmup 早期 fear 误报 ③ safety_bound |
| SFT/DPO 需要真实数据 | 需 P0 开发，勿用内置数据冒充 |
| 进化一轮后变差 | 锚定校验应触发回滚（手动执行）；合成占比是否超 40% |
| 推理慢 | ① max_new_tokens 控制 ② self-consistency N≤5 ③ 待 KV/状态缓存优化（二期） |
